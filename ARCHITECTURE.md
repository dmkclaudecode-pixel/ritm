# Архитектура Rhythm

Приложение: веб-интерфейс (PWA) внутри Android WebView. Без сервера, без ИИ, всё на устройстве.

## Слои (сверху вниз зависят только от нижних)
| Слой | Файлы | Правила |
|---|---|---|
| Данные-справочники | `catalog.js` (типы TYPES, группы), `catalog2.js` (≈560 занятий), `food*.js` | Только данные. Формат строки: `Название\|тип\|минут\|алиасы` |
| Понимание текста | `parser.js`, `nlu.js` | Чистые функции, без DOM и хранилища. Покрыты `tests/phrases.js`, генератором и стресс-набором |
| Чистая логика | `core.js` | Цели в %, аэробика, перерывы. Всё приходит параметрами, покрыто `tests/core.test.js` |
| Интерфейс и состояние | `js/*.js` — настоящие ES-модули с явными `import`/`export`; точка входа `js/main.js` вызывает `init()` модулей в фиксированном порядке | `base` (хранилище `LS`, сон) → `plan` (анализ, подсказки) → `render` (экраны) → `chat` → `parse` → `morning` → `checkins` → `insights` → `routine` → `nudges` → `daily` → `native` |
| Android | `android/` | Мост `RitmNative`, Watcher/Checkins/WalkWatcher/WidgetProvider |

## Данные (localStorage, ключи `ritm:*`)
- `w:<понедельник>` — неделя: `items` (план) и `days[0..6]` (`log[]`, энергия, настроение…)
- запись журнала: `{id,type,name,min,km,tags,plan,...}`; `plan` связывает запись с пунктом плана
- `settings`, `chat`, `routine`, `schema` (версия схемы для миграций)

## Модель целей
Цель = число занятий × обычная длительность типа (`TYPES[t].def`) в минутах. Прогресс — проценты по минутам;
одно занятие даёт не более 1,5 нормы. Запланированное считается по плановым минутам, пока нет реальных.
Плавание: дорожка = 50 м (≈1 мин), `kmMin` = 27 мин/км. Тип `pause` (микро-перерыв, группа `micro`) в цели не входит.
Одна основная категория + теги (`tags`: глаза, растяжка, шаги, улица…).

## Правила разработки
1. Новая логика без интерфейса — в `core.js` (или новый чистый модуль) + тест сразу.
2. Новая фраза/занятие — строка в каталоге + кейс в `tests/phrases.js`.
3. Любое изменение формата данных — миграция по `schema`, старые данные не теряем.
4. До коммита: `npm run lint` (ESLint: необъявленные имена, неиспользуемый код — ошибки) и `node tests/run.js` зелёные. CI делает то же и не соберёт APK при ошибке. Браузерные сценарии — `tests/e2e/*.py` (Playwright, запускать вручную после крупных правок; сервер `python3 -m http.server 8765`).
5. Новый модуль интерфейса: файл в `js/`, импорт в `js/main.js`, имя в `sw.js` (SHELL); `js/*.js` в APK копируется маской, корневые файлы — списком в `.github/workflows/android.yml` и поднять версию кэша в `sw.js`.
6. Не раздувать `js/*.js`: при добавлении крупной функции сначала вынести чистую часть в `core.js`; новый файл интерфейса — в `js/` и в три списка (см. п.5).

## План рефакторинга `app.js` (по очереди, каждый шаг отдельным коммитом с зелёными тестами)
1. [готово] цели, аэробика, перерывы → `core.js`
1б. [готово] монолит `app.js` разрезан на 12 модулей `js/*.js`; зависимости явные (`import`), запись в общие переменные — только через `__set_имя()` из модуля-владельца; действия при запуске собраны в `init()`
2. Хранилище (`LS`, `getWeek/saveWeek`, миграции) → `storage.js`; добавить кэш разбора недель
3. Аналитика и инсайты (`personalInsights`, `weekForecast`, `weakDays`, `habitTimes`) → чистые функции в `insights.js`
4. Чат-логика (`respondRules`, контекст, `followUp`) → `chat.js`
5. [готово] ES-модули. Дальше: убрать циклические импорты между `chat`/`parse`/`insights`/`daily`/`render` (вынести общие функции в нижние слои), заменить `__set_*` на единый объект состояния `state`
6. Когда выйдем за ≈10 МБ данных или медленный старт: IndexedDB, ленивая загрузка каталогов, сборка (esbuild)

## Как добавлять код в модули
- Нужна функция из другого модуля — `import {имя} from "./файл.js"`; линтер сразу скажет, если забыли.
- Нужно, чтобы функцию видели другие модули — `export` перед ней.
- Нужно изменить общую переменную другого модуля (`settings`, `tab`, …) — импортировать `__set_имя` (есть у переменных, которые уже меняются снаружи; для новых добавить в модуль-владелец `export const __set_x = v => (x = v);`).
- Код, который должен выполниться при запуске (подписки на кнопки, миграции, первый `render()`), — внутрь `init()` модуля, а не на верхний уровень: иначе при циклических импортах он может сработать до загрузки зависимостей.

## Движок смысла (engine.js + lexicon.js + catalog3.js)
Порядок: выученное пользователем → его занятия → алиасы каталога (`catalog*.js`) → основы типов → опечатки → **смысловой слой** (`engine.js`).
Смысловой слой — стеммер русского + наивный Байес по основам и кускам слов, обучается при запуске на каталоге, `lexicon.js` и выученных фразах. Включается только для незнакомых слов и слабых догадок; отвечает, когда уверен (p≥0.75, отрыв от второго ≥0.3, есть совпадение по основе слова). Не трогает болтовню, отрицания, сон и общие «тренировка/занимался».
Измерение: `tests/semantic.js` + наборы `tests/semantic/*.js` (train — обучающий, held1/held2 — фразы, которых словарь не видел). Пороги в тесте не дают качеству упасть. Новые слова — в `lexicon.js`/`catalog3.js`, новые фразы для проверки — в новый `held*.js`.
План: онтология связей слов (сочетаемость, контексты), эмбеддинги из открытых ресурсов (собираются в GitHub Actions, у песочницы нет доступа), самообучение связей и уточняющие вопросы.

## Разговорный движок: три модуля (v1)
- **Распознавание** — `parser.js` + `engine.js` + `lexicon.js` (что сделал человек).
- **Настроение** — `mood.js`: `RITM.mood.analyze(text)` → эмоция, валентность, заряд, потребность (support/rest/celebrate/…); учитывает отрицания (в пределах клаузы), усилители, КАПС, «!!!», смайлы; `track/summary` копят историю в `localStorage` (тренд, затяжной спад).
- **Конструктор и контекст** — `dialog.js`: `Context` (память реплик, настроение беседы, тренд, раскрытие «а вчера?»), `compose(frame, ctx)` (фраза по акту+настроению без повторов), `clarify(guesses)` (уточняющий вопрос), `plural/dur`.
- Подключение к чату: `moodReply` в `js/parse.js`. Тесты: `tests/mood.js`.
- Дальше: онтология и эмбеддинги из конвейера знаний (`knowledge-data`), своя языковая модель поверх накопленных диалогов.
- Внимание: `RITM.core` — объект чистой логики (core.js); текстовая функция парсера теперь `RITM.coreText`.

## Онтология слов и словосочетаний (onto.js + data/onto.json)
- Данные собирают GitHub Actions (`corpora.yml`, `knowledge.yml`), в приложение их сжимает `node tools/compact_onto.js <папка>` → `data/onto.json` (~0,5 МБ): продукт→блюда, блюдо→состав, глагол↔продукт, сочетания.
- `RITM.onto`: `lookup(слово)`, `dishesFrom([продукты])`, `askAbout(слово)` (уточняющий вопрос), `learn(слово, понятие, контекст, ±)` — выученные связи в `localStorage`, в основу попадают после 2 подтверждений, поправка ослабляет.
- Подключение: диалог неизвестного слова (`js/parse.js`) предлагает «приём пищи» первым, если слово — еда по онтологии.
- Дальше: Wikidata/ConceptNet/Navec из `knowledge-data`, эмоции слов из `corpora-data`, подключение к `engine.js` как признаков.

## Обновление: настроение, векторы, области слов
- `mood.js` — правила (словарь эмоций, идиомы, отрицания, усилители) + лексикон из корпусов (`data/mood_lex.json`) + векторы слов (`embed.js`, `data/emb.bin`) для незнакомых слов + классификатор (`data/mood_nb.json`, наивный Байес по основам; обучение — `node tools/train_mood_local.js` на фразах `tools/moodtrain/*.txt`, формат «класс|фраза»). Модель и правила суммируются.
- `onto.js`: добавлены `domain` (food/drink/produce/sport/exercise/hobby — из Wikidata, ConceptNet IsA, RuWordNet), `isa`, `typeHint(слово)`. Данные собирает `node tools/compact_onto.js <папка с recipes/collocations/wikidata/conceptnet/ruwordnet>`.
- `trainlog.js` — журнал «фраза → разбор → правка пользователя» на устройстве (ключ `ritm:trainlog`, до 3000 записей, входит в резервную копию).
- Проверки: `tests/fresh/*.js` — свежие наборы (информационно). Правило: набор, по которому подгоняли словарь, больше не считается свежим; для честных цифр пишется новый (последний: `mood_e`).

## Разговор (talk.js)
`RITM.talk.reply({text, mood, ctx})` → {text, act, asked, topic}. Акты: selfneg, andyou, whatsup, botq, advice, ack, mood (эмпатия через `dialog.compose`), event, topic, clarify, invite, short. Правила тона: без вопроса два хода подряд, тема держится по контексту (`Context.topic`), фразы не повторяются (`Context.said`). Подключение: `js/parse.js` — `direct()` до разбора занятий, `moodReply` для сильной эмоции без дела, `chattyReply` вместо шаблонных «Принято». Тесты: `tests/talk.js` (сценарии из нескольких реплик).
